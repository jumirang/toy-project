- [prototype.html](prototype.html): 승인된 화면. 화면 구성, 정보 순서, 상태 표현, 좁은 화면 동작은 이 파일을 따른다. 데이터는 모두 더미다.

## 사용자에게 보이는 결과

1. 관심 기업을 검색해 추가하고 삭제할 수 있다. 목록은 하나이고 로그인은 없다.
2. 월간 캘린더에 관심 기업의 실적 발표일이 보인다. 발표 완료, 예정(확정), 예정(예상)이 서로 구별된다. 기업별로 걸러 볼 수 있고, 달을 넘길 수 있다.
3. 캘린더나 그 달의 발표 목록에서 발표를 고르면 상세 패널에 다음이 나온다.
   - 기업 설명, 업종, 공식 사이트·IR·DART·네이버 증권·에프앤가이드 링크
   - 그 분기의 매출액, 영업이익, 순이익(연결)과 각 항목의 컨센서스 평균·최저·최고, 실적과 컨센서스 평균의 차이 비율
   - 발표 전날 종가 대비 현재(또는 고른 기준일) 종가의 변동률
   - 과거 발표마다 영업이익 컨센서스 대비 결과와 +1일, +5일, +20일, +30일, +60일 주가 반응
   - 최근 5년 PER 또는 PBR 밴드 시계열 차트와, 5년 범위 안에서 현재 위치
   - 최근 뉴스의 제목, 요약, 원문 링크
4. 예정 발표를 고르면 예정일과 그 근거, 다가오는 분기의 컨센서스 평균이 위에 나오고, 나머지는 직전 발표 기준으로 보인다.
5. 컨센서스 평균은 뉴스 요약문이 정해진 문장 패턴에 맞으면 자동으로 채워지고, 사용자가 고칠 수 있다. 채워지지 않은 항목은 직접 입력하며, 옆에 관련 기사 링크가 보인다. 최저·최고는 사용자가 직접 입력한다. 값마다 출처(뉴스 또는 직접 수정)가 표시된다.
6. `전체 갱신` 버튼으로 관심 기업 전체의 데이터를 최신으로 가져온다. 진행 상황과 마지막 갱신 시각이 보이고, 일부 기업이 실패하면 어느 기업이 왜 실패했는지와 재시도 수단이 보인다.

## 승인된 범위

- 관심 기업 목록 관리(추가, 삭제)
- 실적 발표일 캘린더(과거, 확정 예정, 예상 예정)와 예정일 수정
- 발표 상세: 기업 정보와 링크, 실적과 컨센서스, 차이 비율, 발표 후 주가 변동률, 과거 발표별 반응 표, PER/PBR 밴드 차트, 최근 뉴스
- 뉴스 요약문의 규칙 기반 컨센서스 평균 추출과 사용자 수정, 최저·최고 직접 입력
- 사용자가 직접 적는 기업 설명
- 데이터 보관과 수동 전체 갱신
- 갱신 실패, 관심 기업 없음 상태

## 수용 기준

실행 중인 앱을 브라우저로 열어 확인한다. 외부 API는 실제 키로 호출한다.

- AC1. 관심 기업이 없을 때 빈 상태와 `관심 기업 추가` 동작이 보이고, 캘린더와 상세는 보이지 않는다.
- AC2. 기업명이나 종목코드 일부로 국내 상장 기업을 검색해 추가하면 목록과 필터에 나타나고, 삭제하면 사라진다. 새로고침이나 앱 재시작 뒤에도 목록이 유지된다.
- AC3. 갱신 후, 관심 기업의 최근 4개 분기 이상의 과거 발표일이 캘린더의 해당 날짜에 "발표 완료"로 표시된다. 날짜는 DART의 영업(잠정)실적(공정공시) 접수일과 같다.
- AC4. 다음 분기 발표가 아직 없는 기업은 예정일이 표시된다. DART에 그 분기 실적을 위한 기업설명회(IR) 개최 공시가 있으면 그 날짜에 "확정"으로, 없으면 작년 같은 분기 발표일을 기준으로 한 날짜에 "예상"으로 표시되고, 상세에 근거가 적힌다.
- AC5. 사용자가 예정일을 고치면 캘린더와 상세에 고친 날짜가 보이고, 다음 갱신 뒤에도 유지된다.
- AC6. 발표 완료 건을 고르면 매출액, 영업이익, 순이익의 실적이 해당 잠정실적 공시의 당해 분기 값(연결)과 같다.
- AC7. 차이 비율은 `(실적 - 컨센서스 평균) / |컨센서스 평균| × 100`이며, 컨센서스 평균이 없는 항목은 `—`로 보인다. 상승·호실적은 빨강, 하락·부진은 파랑으로 보인다.
- AC8. 갱신 후 컨센서스 평균이 뉴스 요약문에서 찾아진 항목은 값과 함께 출처 기사(제목, 매체, 날짜, 링크)가 보인다. 찾지 못한 항목은 비어 있고, 그 분기 발표 전 30일 안의 관련 기사 링크가 함께 보인다.
- AC8a. 컨센서스 추출 규칙은 한 요약문 안에서 분기(또는 발표 대상 분기를 가리키는 표현), 항목(매출액·영업이익·순이익), 컨센서스를 뜻하는 말(컨센서스, 시장 전망치, 증권가 추정치 등), 금액이 함께 나올 때만 값을 낸다. "10조4천억 원", "1조 2,300억원", "5212억원" 같은 한국어 금액 표기를 억원 단위 숫자로 바르게 바꾼다. 다른 분기나 연간 값, 컨센서스가 아닌 실적 숫자만 있는 요약문에서는 값을 내지 않는다. 이 동작은 실제 네이버 뉴스 요약문에서 모은 예시로 만든 자동 테스트로 증명한다.
- AC9. 사용자가 컨센서스 평균을 고치거나 최저·최고를 입력하면 차이 비율이 바로 다시 계산되고 출처가 "직접 수정"으로 바뀐다. 이후 갱신이 사용자 값을 덮어쓰지 않는다.
- AC10. 발표 후 주가 변동률은 발표 전날 종가와 현재(가장 최근 거래일) 종가로 계산된다. 기준일을 바꾸면 그날(휴장일이면 직전 거래일) 종가로 다시 계산된다.
- AC11. 과거 발표별 표의 +N일 값은 발표 전날 종가 대비 발표일로부터 N번째 거래일 종가의 변동률이다. 아직 N거래일이 지나지 않은 칸은 `—`다.
- AC12. PER/PBR 밴드 차트는 최근 5년 월말 주가 선과 5개 배수 선을 그린다. 배수 선은 5년 동안의 월말 배수 최저값부터 최고값까지 균등하게 나눈 값이다. PER과 PBR을 전환할 수 있고, 마우스를 올리면 그 달의 주가와 배수가 보인다. 차트 위에 현재 배수와 5년 범위 안에서의 위치(하위 ○%)가 보인다.
- AC13. 기업 상세에 업종, 공식 사이트 링크(DART 기업개황에 있으면 IR 링크도)와 DART, 네이버 증권, 에프앤가이드의 해당 종목 페이지 링크가 보인다. 기업 설명은 사용자가 적어 저장할 수 있고, 적지 않았으면 설명을 적으라는 안내가 보인다.
- AC14. 최근 뉴스는 관심 기업별로 제목, 요약, 매체·날짜, 원문 링크를 보여 주고 기사 본문은 보여 주지 않는다.
- AC15. `전체 갱신`을 누르면 진행 상황이 보이고 버튼이 다시 눌리지 않으며, 끝나면 마지막 갱신 시각이 바뀐다. 한 기업의 외부 호출이 실패해도 나머지는 갱신되고, 실패한 기업과 이유, 그 기업만 다시 갱신하는 수단이 보이며, 실패한 기업은 이전 데이터를 그대로 보여 준다.
- AC16. 매수·매도를 권하거나 신호를 표시하는 문구나 표시가 어디에도 없다.
- AC17. 390px 폭에서 정보 순서를 유지한 채 한 열로 쌓이고, 캘린더 칸은 점으로 발표를 표시하며 그 달의 발표 목록으로 고를 수 있다.

## 확정된 제약과 근거

- 로그인과 계정 구분 없이 관심 기업 목록 하나로 시작한다(**임시**, 아래 "미뤄 둔 결정" 참고). 사용자가 서비스가 잘 만들어진 뒤 계정을 추가하겠다고 했다.
- 데이터는 Supabase에 보관하고, 화면은 보관된 데이터를 보여 준다. 매번 외부 사이트를 오가지 않기 위해서다. (사용자 확정)
- 실적과 과거 발표일은 DART OpenAPI에서 가져온다. 발표 당일의 실적은 정기보고서보다 한 달 이상 앞서는 영업(잠정)실적(공정공시)에서 읽는다. 정형 재무 API(정기보고서 재무정보)는 분기보고서가 나온 뒤에만 값을 주기 때문이다. (DART OpenAPI 가이드에서 확인, 2026-11-19)
- 주가는 공공데이터포털 "금융위원회_주식시세정보"에서 가져온다. 실시간이 아니라 전 거래일 종가 기준이다.
- 컨센서스 평균은 네이버 검색 API(뉴스)의 요약문에서 정해진 문장 패턴으로 추출한다. 에프앤가이드는 `robots.txt`가 `Disallow: /`로 모든 자동 수집을 막고 있고(`wcomp.fnguide.com`, `comp.fnguide.com`, 2026-11-19 확인), 컨센서스의 무료 정식 출처가 없어서 뉴스를 쓴다. (사용자 확정)
- LLM이나 유료 API를 쓰지 않는다. 사용자가 유료 API를 쓸 수 없다고 했다. Claude 앱이나 ChatGPT 앱의 구독 계정은 서비스 코드에서 호출하는 API와 별개라 대신 쓸 수 없다. 그래서 패턴에 맞지 않는 요약문은 빈칸으로 두고 직접 입력에 맡긴다. (사용자 확정)
- 기업 설명은 사용자가 직접 적는다. 사업보고서를 줄여 설명을 만들려면 LLM이 필요해서다. 업종과 링크는 DART 기업개황에서 자동으로 가져온다. (사용자 확정)
- 이용을 허락하지 않은 사이트의 화면을 자동으로 수집하지 않는다. 뉴스는 검색 API가 주는 제목, 요약, 링크만 쓰고 기사 본문을 가져오지 않는다. (PRODUCT.md 경계)
- 예정일은 DART의 기업설명회(IR) 개최 공시가 있으면 확정, 없으면 작년 같은 분기 발표일 기준 예상으로 표시하고 사용자가 고칠 수 있다. 앞으로의 발표일을 주는 정식 API가 없어서다. (사용자 확정)
- 갱신은 사용자가 누르는 `전체 갱신` 버튼으로만 한다(**임시**, 아래 "미뤄 둔 결정" 참고). 본인 PC 같은 비공개 환경에서 쓰는 동안에는 예약 작업이 앱 실행 여부에 묶이기 때문이다. (사용자 확정)
- 판단 재료만 보여 주고 매수·매도 신호를 내지 않는다. (PRODUCT.md 경계)

## 가정 (바꿀 수 있음)

- 실적은 연결 기준 분기 값이다. 순이익은 잠정실적 공시의 당기순이익을 쓴다.
- 과거 발표별 표는 최근 8개 분기까지 보여 준다.
- 발표가 장 마감 뒤에 나와도 "발표 전날 종가"는 발표일 전 거래일 종가다.
- PER은 최근 4개 분기 합산 연결 당기순이익, PBR은 최근 분기말 연결 자본총계를 상장주식수로 나눈 값으로 계산한다. DART 주요계정 API에는 지배주주 값이 없어서 연결 전체 값을 쓴다. 월말 주가와 그 시점까지 분기가 끝난 재무를 쓰고, 4분기 순이익은 연간 값에서 3분기 누적을 뺀다. 차트 세로축은 주가 범위에 맞추고, 일회성 이익 등으로 범위를 벗어난 밴드 선은 잘라서 보여 준다.
- 뉴스 매체 이름은 검색 API가 주지 않아 기사 주소의 도메인으로 보여 준다.
- 뉴스에서 뽑은 컨센서스 평균이 그 분기 실적(없으면 직전 분기 실적)의 1/3–3배 밖이면 기사 속 다른 숫자로 보고 버린다.
- 뉴스 검색어는 기업명과 "실적", "영업이익", "컨센서스"를 조합한다. 컨센서스 추출에는 발표일 전 30일 안의 기사만 쓴다.
- 같은 항목에 컨센서스 평균을 준 기사가 여러 개면 발표일에 가장 가까운 기사의 값을 쓴다.
- 상승은 빨강, 하락은 파랑이다(국내 관례).
- 관심 기업 수에 상한을 두지 않는다. 10개 안팎을 권장 문구로만 보여 준다.

## 범위 밖과 이유

- 로그인, 계정별 관심 기업, 사용자별 컨센서스 값: 사용자가 이번에는 빼기로 했다.
- 매일 자동으로 모으는 예약 작업과 서버 배포: 갱신 버튼으로 대신한다.
- 산업 성장률(업황) 지표: PRODUCT.md에서 아직 정하지 않은 항목이다.
- 해외 종목, 실시간 시세: PRODUCT.md 경계 밖이다.
- 에프앤가이드·네이버 증권 화면 수집, 유료 컨센서스 데이터: 위 제약 참고.
- 매수·매도 신호, 목표가, 알림: PRODUCT.md 경계 밖이다.
- 보안 하드닝, 엣지케이스·성능 방어: AGENTS.md 검증·리뷰 예산.

## 미뤄 둔 결정

- **계정과 사용자별 데이터**: 지금은 목록 하나, 컨센서스 값 하나다. 다시 열 조건: 이 스펙이 main에 반영된 뒤 사용자가 계정 기능 추가를 요청할 때. 그때 PRODUCT.md의 사용자 정의와 함께 다시 정한다.
- **자동 예약 갱신**: 지금은 `전체 갱신` 버튼만 있다. 다시 열 조건: 서비스를 본인 PC가 아닌 서버에 배포하기로 할 때.

## 남은 위험

- 규칙 기반 추출은 표현이 조금만 달라도 놓친다. 뉴스 요약문에 컨센서스가 없거나 다른 분기·연간 값만 있는 경우까지 더해지면 빈칸이 늘어 직접 입력 부담이 커진다. 빈칸이 너무 많다고 느껴지면, Claude Code 명령으로 추출하는 방식이나 소액 API 결제(LLM 추출)를 다시 검토한다.
- 기사가 인용한 컨센서스는 기사 시점의 값이라 발표 직전 값과 다를 수 있다.
- 잠정실적 공시를 내지 않는 기업(주로 중소형주)은 발표일과 실적이 분기보고서 시점에야 잡힌다.
- 잠정실적 공시 원문의 표 형식이 기업마다 조금씩 달라 일부 항목을 읽지 못할 수 있다.
- 공공데이터포털과 네이버 검색 API의 일일 호출 한도 안에서 5년치 시세를 처음 채우는 데 시간이 걸릴 수 있다.
- NAVER API HUB 검색 API는 지금 한시적으로 무료이고, 나중에 종량제로 바뀔 수 있다(사전 공지 예정). 월 한도에 닿으면 호출이 자동으로 차단되므로 모르는 사이에 요금이 쌓이지는 않는다. 유료로 바뀌면 유료 API를 쓰지 않는다는 제약과 충돌하므로 뉴스 출처를 다시 정한다.
- 로그인이 없으므로 인터넷에 공개하면 누구나 관심 기업과 컨센서스를 바꿀 수 있다. 비공개 환경에서만 쓴다는 전제다.

## Setup before implementation

- Supabase Cloud 프로젝트 1개 — 관심 기업과 수집 데이터 보관 — 완료 조건: Supabase 대시보드에 프로젝트가 보이고 Project URL과 anon(publishable) 키를 확인할 수 있다.
- DART OpenAPI 인증키 — 실적, 발표일, IR 공시, 기업개황 조회 — 완료 조건: 브라우저나 터미널에서 `https://opendart.fss.or.kr/api/company.json?crtfc_key=<키>&corp_code=00126380` 호출이 `"status":"000"`을 돌려준다.
- 공공데이터포털 "금융위원회_주식시세정보" 활용신청 승인 — 일별 종가와 상장주식수 조회 — 완료 조건: 포털 마이페이지에서 승인 상태가 보이고, 서비스키로 `getStockPriceInfo`를 직접 호출하면 `resultCode`가 `00`이다.
- NAVER API HUB(네이버 클라우드 플랫폼) 검색 API 키 — 뉴스 수집과 컨센서스 추출 입력 — 완료 조건: Client ID와 Secret을 `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY` 헤더로 넣어 `https://naverapihub.apigw.ntruss.com/search/v1/news?query=삼성전자` 직접 호출이 200을 돌려준다. 네이버 개발자센터의 검색 API가 NAVER API HUB로 옮겨 갔다.
