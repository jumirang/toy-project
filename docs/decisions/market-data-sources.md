# 시장 데이터 출처

## Decisions

- 실적 발표일과 실적은 DART OpenAPI에서 가져온다. 발표 당일 실적은 영업(잠정)실적(공정공시) 원문에서 읽고, 발표일은 그 분기 첫 잠정공시의 접수일이다.
- 한 분기에 속보, 상세, 정정 공시가 섞이면 항목이 가장 많이 채워진 공시의 값을 쓴다. 원문 양식은 "실적기간" 줄, `('25.2Q)`, `2025년 2분기` 세 가지가 있다.
- 다음 발표 예정일은 직전 분기의 마지막 공시 이후 열리는 실적 관련 기업설명회(IR) 공시가 있으면 확정, 없으면 작년 같은 분기 발표일 기준 예상으로 둔다. 사용자가 고친 날짜를 우선한다.
- 주가는 공공데이터포털 "금융위원회_주식시세정보" V2(`GetStockSecuritiesInfoService_V2/getStockPriceInfo_V2`)에서 전 거래일 종가로 가져온다.
- PER/PBR은 DART 주요계정의 연결 당기순이익(최근 4개 분기 합)과 연결 자본총계를 상장주식수로 나눠 계산한다. 4분기 순이익은 연간 값에서 3분기 누적을 뺀다.
- 뉴스와 컨센서스 원문은 NAVER API HUB 뉴스 검색(`naverapihub.apigw.ntruss.com/search/v1/news`)의 제목과 요약만 쓴다. 기사 본문은 가져오지 않는다.
- 컨센서스 평균은 뉴스 요약문에서 규칙 기반으로 뽑는다. 대상 분기, 항목, 컨센서스를 뜻하는 말, 금액, 기업 이름이 한 문장에 있을 때만 값을 내고, 그 분기 실적(없으면 직전 분기 실적)의 1/3–3배 밖이면 버린다. 최저·최고와 빈 평균은 사용자가 입력하고, 사용자가 고친 값은 갱신이 덮어쓰지 않는다.
- LLM이나 유료 API를 쓰지 않는다.

## Boundaries

- 이용을 허락하지 않은 사이트의 화면은 자동으로 수집하지 않는다. 다른 사이트로 가는 링크는 걸어도 된다.
- 주요계정 API에는 지배주주 순이익과 자본이 없어서, PER/PBR은 연결 전체 값 기준이다.

## Why

컨센서스는 증권사 추정치를 모은 상용 데이터라 무료 정식 출처가 없다. 그래서 공개 뉴스가 인용한 평균을 쓰고, 틀린 값보다 빈칸이 낫다는 기준으로 규칙을 보수적으로 둔다. 사용자는 유료 API를 쓸 수 없고, Claude나 ChatGPT 앱 구독은 서비스 코드에서 호출하는 API와 별개라 대신 쓸 수 없다.

## Reconsider when

- 빈 컨센서스가 많아 직접 입력 부담이 크다고 사용자가 느낄 때. Claude Code 명령으로 추출하는 방식이나 소액 API 결제(LLM 추출)를 검토한다.
- NAVER API HUB 검색 API가 한시 무료에서 유료로 바뀔 때. 뉴스 출처를 다시 정한다.
- 컨센서스 유료 데이터(에프앤가이드, WiseFn 등) 계약을 검토할 예산이 생길 때.

## Still-rejected alternatives

- 에프앤가이드·네이버 증권 컨센서스 화면 수집 — `wcomp.fnguide.com`, `comp.fnguide.com`의 `robots.txt`가 `Disallow: /`이고(2026-11-19 확인), 네이버 증권 컨센서스도 에프앤가이드 공급 데이터다. 약관 위반 소지와 화면 변경 시 갱신이 깨지는 위험이 있다. 해당 사이트가 이용을 허락할 때만 다시 본다.
- 구글 뉴스 — 공식 뉴스 검색 API가 없고, RSS는 요약문이 없어 컨센서스 숫자를 뽑을 재료가 부족하다.
- 정기보고서 재무 API만으로 실적 읽기 — 분기보고서는 실적 발표보다 한 달 이상 늦어 발표 당일 비교가 안 된다.

## Evidence worth preserving

- 실제 기사에서 재현한 오추출: "매출액과 영업이익 전망치(컨센서스)는 각각 3조5143억원, 4976억원"에서 첫 금액이 영업이익으로 들어가던 문제, "네카오"처럼 두 회사를 다룬 기사, 기사 속 다른 숫자("9억원", "385억원"). 모두 `features/consensus/extract.test.ts`에 테스트로 고정했다.
- 삼성전자는 첫 잠정공시 뒤에 같은 분기 실적설명회 IR 공시를 내므로, 그 IR을 다음 분기 예정일로 읽으면 안 된다.
