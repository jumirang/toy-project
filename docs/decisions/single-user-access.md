# 로그인 없는 단일 사용자 운영

## Decisions

- 로그인과 계정 구분 없이 관심 기업 목록 하나, 컨센서스 값 하나로 운영한다.
- Supabase 테이블은 RLS를 켜되 anon 역할에 읽기·쓰기를 모두 연다. 서버에서 publishable 키로 접근한다.
- 데이터 갱신은 사용자가 누르는 `전체 갱신` 버튼으로만 한다. 예약 작업은 없다.
- 처음 설치할 때 삼성전자와 SK하이닉스를 기본 관심 기업으로 넣는다. 지우면 다시 생기지 않는다.

## Boundaries

- 비공개 환경에서만 쓴다는 전제다. 인터넷에 공개된 주소에서는 누구나 관심 기업과 컨센서스를 바꿀 수 있다.

## Why

사용자가 계정 기능은 서비스가 잘 만들어진 뒤에 추가하겠다고 했다. 예약 갱신은 본인 PC에서 쓰는 동안 앱 실행 여부에 묶여 의미가 없어 버튼으로 대신했다.

## Reconsider when

- 사용자가 계정 기능 추가를 요청할 때. PRODUCT.md의 사용자 정의와 함께, 관심 기업과 컨센서스 값을 계정별로 나누고 anon 권한을 닫는다.
- 서비스를 본인 PC가 아닌 서버에 배포해 쓸 때. 예약 갱신을 다시 정하고, 공개 주소라면 로그인 없이 쓰기를 열어 둔 상태를 함께 다시 본다.
