# 계정과 데이터 접근

## Decisions

- 이메일/비밀번호로 가입·로그인한 계정 단위로 운영합니다. 가입 없이 들어오는 둘러보기는 읽기 전용입니다.
- 외부 출처에서 수집한 데이터(실적, 발표일, 주가, 뉴스, 뉴스에서 자동 추출한 컨센서스 평균)는 공통 데이터이고, 기업당 한 벌만 보관합니다. 로그인 여부와 관계없이 읽을 수 있습니다.
- 관심 기업 목록과 사용자가 직접 입력하거나 고친 값(컨센서스 평균·최저·최고, 기업 설명, 예정일)은 계정별 데이터이고, 그 계정만 읽고 바꿀 수 있습니다. 로그아웃 상태에서는 계정별 데이터에 접근할 수 없습니다.
- 공통 데이터의 갱신은 로그인한 사용자가 자기 관심 기업에 대해 누르는 `전체 갱신`이나 기업별 갱신으로만 합니다. 갱신 결과는 모든 계정과 둘러보기에 반영됩니다. 예약 작업은 없습니다.
- 둘러보기에서는 기본 기업(삼성전자, SK하이닉스)만 보이고, 갱신과 모든 쓰기를 할 수 없습니다. 보이는 컨센서스는 공통 데이터의 자동 추출 값뿐입니다.
- 새 계정에는 가입 직후 기본 기업 둘을 관심 기업으로 넣습니다. 지우면 다시 생기지 않습니다.

## Boundaries

- 화면 구성을 정하는 결정이 아닙니다.
- 계정별 값이 없는 항목은 공통 데이터의 값을 보여 줍니다. 계정별 값은 공통 데이터를 덮어쓰지 않고 그 계정의 화면에서만 우선합니다.
- 공통 데이터를 쓰는 갱신은 로그인한 사용자만 할 수 있습니다. 로그아웃 상태의 쓰기 요청은 거부합니다.

## Why

한 사람이 고친 컨센서스가 다른 사람 화면을 바꾸면, 서비스를 공개했을 때 누구나 모두의 값을 바꿀 수 있습니다. 그래서 사용자가 입력한 값은 계정에 묶습니다. 반대로 수집한 시장 데이터까지 계정별로 나누면 같은 기업을 계정마다 외부에서 따로 가져와야 해서, 일일 호출 한도를 계정 수만큼 소모합니다. 그래서 수집 데이터는 기업당 한 벌만 둡니다. 예약 갱신은 본인 PC에서 쓰는 동안 앱 실행 여부에 묶여 의미가 없어 버튼으로 대신합니다.

## Reconsider when

- 서비스를 본인 PC가 아닌 서버에 배포해 자동 예약 갱신을 도입할 때. 둘러보기 데이터의 최신성도 함께 다시 정합니다.
- 계정별 컨센서스 입력이 사용자에게 너무 큰 부담이라는 근거가 생길 때
- 가입이 늘어 갱신이 외부 API 호출 한도를 넘길 때. 갱신 권한을 다시 정합니다.

## Still-rejected alternatives

- 로그인 없이 목록 하나, 컨센서스 값 하나로 운영하는 방식 — 공개 주소에서는 누구나 모두의 관심 기업과 컨센서스를 바꿉니다. 사용자가 계정 기능을 요청해 대체했습니다.
- 관심 기업 목록만 계정별로 나누고 고친 값은 전체가 공유하는 방식 — 구현은 단순하지만 공개 배포 시 한 사람이 모두의 값을 바꿉니다. 공유 값에 대한 수정 권한을 따로 정하는 시점에 다시 봅니다.
- 관리자나 예약 작업만 공통 데이터를 갱신하는 방식 — 현재 범위인 수동 갱신을 넘고 별도 배포가 필요합니다. 자동 예약 갱신을 도입할 때 다시 봅니다.
